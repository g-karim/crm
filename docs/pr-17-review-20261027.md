## Исправления CRM

1. `server-tests.yml` и `migration-test.yml` ссылались на старый Messenger
   `ed2951c5…`, пропуская 32 последующих коммита. Оба workflow теперь выбирают head
   согласованного PR #16.
2. Найден сопутствующий дефект установленной `frappe-ui`: даже при отключённой
   телеметрии plugin загружал удалённый Pulse client с CDN. CRM теперь устанавливает
   plugin только после явного `enabled=true` и полной конфигурации от backend.
   Неуспешная загрузка конфигурации оставляет телеметрию выключенной. Добавлены
   9 тестов opt-out, отсутствующего backend и сохранения разрешённой конфигурации.
3. Счётчик внешнего HTTP в User API E2E сохраняет безопасную диагностику origins
   и отдельно считает встроенные `data:`/`blob:` ответы. Запрет внешнего HTTP сохранён.

## Границы результата и публикация

У Wazzup использовались только локальный имитатор и mock transport. Реальные
Account, QR, тарифы и доставка через Wazzup не проверялись. Gateway HMAC подтверждает
локальный gateway, а не происхождение webhook от самого Wazzup.

Локальная MariaDB 11.8 запускалась с `innodb_snapshot_isolation=OFF`, чтобы
соответствовать MariaDB 10.6 из CI. Совместимость со строгим режимом `ON` не
подтверждена; в исходном окружении получены ошибки 1020. Конфигурация существующих
БД не изменялась.

При отдельном разрешении на публикацию сначала нужен commit исправлений Messenger,
затем **оба** pin в CRM следует заменить его фактическим SHA. Текущий `443ac7c…`
соответствует проверенному опубликованному head #16; локальные исправления пока
не имеют commit SHA. После push требуется проверить настоящие CI checks.

Общий отчёт, патчи и evidence находятся в локальном каталоге review workspace
`crm-pr-review-20261027`. Реальный запуск Wazzup и production release этим ревью
не выполнялись.
