# Подключение мессенджеров к CRM

CRM Messenger позволяет принимать сообщения из WhatsApp, Telegram, VK, MAX и Avito и отвечать на них из карточки лида.
Для каждого бота, сообщества или внешнего канала создаётся отдельный канал CRM. Telegram-боты, VK, MAX и Avito подключаются напрямую; WhatsApp и личные чаты Telegram — через Wazzup.

## Перед началом

- CRM должна быть доступна из интернета по постоянному публичному HTTPS-адресу с действующим TLS-сертификатом.
- Для MAX внешний HTTPS-адрес должен использовать стандартный порт 443.
- Для переписки Avito в CRM нужна подписка с доступом к Messenger API. Если Avito возвращает список чатов без подписки, доступно автоматическое создание лидов и переход в чат на Avito.
- В Frappe должны работать веб-процессы, фоновые обработчики и планировщик.
- Настраивать каналы может Administrator или пользователь с ролью «Системный менеджер».
- Токены и client credentials дают доступ к внешнему аккаунту: не передавайте их посторонним и не добавляйте в исходный код.

Если приложение еще не установлено, выполните в каталоге bench:

```bash
bench get-app https://github.com/g-karim/crm_messenger.git
bench --site <имя-сайта> install-app crm_messenger
bench --site <имя-сайта> migrate
bench --site <имя-сайта> clear-cache
bench restart
```

## Общая настройка CRM

1. Откройте **Настройки → Интеграции → Каналы сообщений**.
2. Включите **Обмен сообщениями**.
3. При необходимости включите **Создавать лиды из новых диалогов**. Тогда первое обращение нового клиента создаст лид автоматически.
4. Нажмите **Сохранить настройки**.
5. Нажмите **Новый канал**, выберите провайдера и заполните данные подключения.
6. Для прямых интеграций нажмите **Создать канал**, откройте его и последовательно нажмите **Проверить** и **Подключить / исправить**. Для WhatsApp и личных чатов Telegram нажмите **Подключить** и завершите авторизацию в этой же форме.

В прямых интеграциях адрес и секрет вебхука вводить вручную не нужно: CRM создаёт и регистрирует их автоматически. После успешного подключения канал включается и получает статус **Подключён**.

## Telegram-бот

### Получение токена

1. Откройте в Telegram официального бота [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot` и укажите название и имя пользователя нового бота.
3. Скопируйте выданный токен.

### Подключение в CRM

Создайте канал и заполните:

- **Провайдер** – **Telegram-бот**;
- **Название канала** – произвольное название, например «Поддержка» (необязательно);
- **Токен бота** – токен от BotFather.

Сохраните канал, затем нажмите **Проверить** и **Подключить / исправить**. CRM проверит токен, получит данные бота и зарегистрирует вебхук.

Для проверки откройте бота под обычным аккаунтом Telegram и отправьте ему `/start` или текст. В CRM должен появиться диалог и, если включено автосоздание, новый лид. Ответьте клиенту из раздела **Переписка** в карточке лида.

> Инструкция выше описывает работу с личными диалогами с ботом. Telegram Business текущей интеграцией не поддерживается.

## VK

### Подготовка сообщества

1. Создайте сообщество VK или откройте управление существующим.
2. Включите **Сообщения сообщества**.
3. Откройте **Управление → Работа с API → Ключи доступа** и создайте ключ доступа сообщества.
4. Разрешите ключу доступ к сообщениям и управлению сообществом. Для отправки изображений и документов также предоставьте права на фотографии и документы.
5. Скопируйте ключ и ID или короткое имя сообщества.

Настраивать Callback API вручную не требуется.

### Подключение в CRM

Создайте канал и заполните:

- **Провайдер** – **VK**;
- **Название канала** – произвольное название (необязательно);
- **Сообщество VK** – числовой ID или короткое имя сообщества;
- **Токен доступа сообщества** – созданный ключ.

Сохраните канал, нажмите **Проверить**, затем **Подключить / исправить**. CRM определит ID сообщества, создаст или обновит сервер Callback API и включит необходимые события.

Для проверки отправьте сообщение сообществу с любого аккаунта VK и ответьте из появившегося лида.

## MAX

### Создание бота и получение токена

1. Подключитесь к [платформе MAX для партнёров](https://business.max.ru/) и создайте верифицированный профиль организации, ИП или самозанятого.
2. В разделе **Чат-боты** нажмите **Создать**, заполните данные бота и дождитесь успешного прохождения модерации.
3. После модерации откройте **Чат-боты → Перейти → Расширенные настройки → Настроить**. Скопируйте значение из поля **Токен**.
Токен также можно получить через мини-приложение или бота **«MAX для бизнеса»**.

### Подключение в CRM

Создайте канал и заполните:

- **Провайдер** – **MAX**;
- **Название канала** – произвольное название (необязательно);
- **Токен бота** – токен бота MAX.

Сохраните канал, нажмите **Проверить**, затем **Подключить / исправить**. CRM получит данные бота и зарегистрирует подписку на события.

Для проверки откройте бота под обычным аккаунтом MAX, запустите его и отправьте сообщение. Затем ответьте из появившегося лида.

> Инструкция выше описывает работу с личными диалогами с ботом.

## Avito

### Подготовка аккаунта

1. Для чтения и отправки сообщений в CRM подключите подписку с Messenger API. Для автоматического создания лидов достаточно, чтобы API аккаунта возвращал список чатов.
2. Получите в Avito `Client ID` и `Client Secret` приложения с доступом к этому аккаунту.
3. Для полной переписки CRM должна иметь постоянный публичный HTTPS-адрес для webhook. В режиме только лидов CRM сама опрашивает Avito; входящий webhook для этого режима не требуется.

### Подключение в CRM

Создайте канал и заполните:

- **Провайдер** — **Avito**;
- **Название канала** — произвольное название (необязательно);
- **Client ID** — Client ID приложения Avito;
- **Client Secret** — Client Secret приложения Avito.

Других пользовательских способов подключения Avito нет: API token и OAuth скрыты и запрещены для новых каналов. Сохраните канал, нажмите **Проверить**, затем **Подключить / исправить**. CRM получит временный access token, определит ID и имя аккаунта через Avito API и проверит доступ. При доступной переписке зарегистрирует webhook; при доступном списке чатов с уведомлением об отсутствии подписки включит режим автоматического создания лидов.

Новый диалог сначала должен начать клиент на Avito. После входящего webhook либо ближайшего discovery CRM получает `chat_id`, создаёт Conversation и, если включено автосоздание, Lead. Discovery выполняется каждые пять минут и также обновляет имя клиента; вручную изменённое имя Lead не перезаписывается.

### Режим без доступа к переписке

Включите **Автоматически создавать лиды** в настройках мессенджера. После подключения и далее каждые пять минут CRM обходит список чатов, создаёт лиды, сохраняет доступные имя клиента и данные объявления. Первое подключение может импортировать существующие чаты согласно выбранному режиму. Чаты, созданные после подключения, создают лиды и без доступа к переписке, если Avito передаёт дату создания. Если Авито скрывает данные сообщений, новую активность в старом чате не всегда удаётся подтвердить; такой чат остаётся в статусе «без подтверждения». Один внешний чат соответствует одному диалогу CRM; повторный обход не создаёт новый лид. Разные чаты одного клиента остаются отдельными обращениями.

На вкладке сообщений показываются причина недоступности переписки и кнопка **Открыть чат на Авито**. Тексты сообщений и поле отправки скрыты. Если точную ссылку нельзя сформировать, кнопка открывает входящие Avito. Уведомление CRM появляется при обнаружении нового чата и изменении времени его обновления; без содержимого сообщений это признак активности чата, а не подтверждённый счётчик новых входящих.

У новых лидов Avito источник **Avito** устанавливается и при обходе чатов, и при получении вебхуков. Миграция заполняет пустой источник у ранее связанных лидов. Непустой источник не перезаписывается. В списке лидов доступен фильтр по источнику.

После подтверждения доступа к реальным сообщениям CRM снимает ограничение, а следующий обход запускает загрузку истории в существующий лид. Для получения новых событий через webhook повторно нажмите **Подключить / исправить**. **Отключить** останавливает автоматический обход канала.

Этот режим использует метаданные, реально возвращённые API: если Avito вместо списка чатов возвращает отказ доступа, создать лиды из такого ответа невозможно. Работа зависит от доступа конкретного аккаунта, активности планировщика и фоновых обработчиков.

### Полная переписка

Поддерживаются входящие текст, изображения, голосовые сообщения и геолокация. Из CRM можно отправить текст или одно изображение без подписи. Исходящие replies, voice/location/file/video и typing для Avito не поддерживаются.

Статусы исходящего Avito-сообщения:

- одна серая галочка — Avito вернул ID сообщения (`sent`); отдельного подтверждения доставки Avito API не предоставляет;
- две синие галочки — клиент прочитал сообщение (`read`), что подтверждено полем `read` в истории либо более поздним входящим сообщением клиента;
- `unknown` — результат запроса неоднозначен; автоматический повтор отключён, чтобы не создать дубль;
- `failed` — Avito явно отклонил отправку.

Когда менеджер открывает входящие в CRM, CRM отдельно помечает весь чат прочитанным со стороны продавца. Это не является подтверждением чтения наших исходящих клиентом.

## WhatsApp и личные чаты Telegram

Основной путь: **Настройки → Интеграции → Каналы сообщений → Новый канал**.
В поле **Провайдер** выберите **WhatsApp** или **Личные чаты Telegram**, задайте название и нажмите
**Подключить**. CRM подготовит подключение, покажет QR и при необходимости
запросит пароль двухфакторной авторизации. Дождитесь подтверждения подключения.
Всё проходит в общей форме **Новый канал**, без открытия второго modal.
Нажмите **Закрыть**. Чтобы снова открыть настройки, нажмите на канал в списке: появится
**Настройка канала** с названием, платформой, статусом и действиями **Обновить статус**,
**Переподключить**, **Удалить канал**. QR и 2FA видны только когда нужны.
Имя можно задать до подключения; после создания оно доступно только для чтения.
API-ключ и UUID канала вводить не требуется: backend сохраняет внешний ID сам.
Для Telegram-бота используйте отдельный вариант **Telegram-бот**.

На текущем этапе Partner API v2 работает с локальным dev/test simulator.
Если подключение на стенде не настроено, диалог сообщает об этом. Настоящий
провайдер пока не подключён.

Для ручной проверки разработчик оставляет `bench start` работающим и запускает
из `apps/crm_messenger`:

```bash
python scripts/run_wazzup_partner_simulator.py --site test16.localhost
```

После сообщения о готовности обновите CRM и пройдите тот же путь. Вместо
сканирования телефоном нажмите **Имитировать сканирование QR**. В тестовом
Telegram-сценарии используйте пароль `simulator-2fa-password`.

Для проверки переписки включите **Обмен сообщениями** и **Создавать лиды из новых
диалогов**, сохраните настройки. Подключите канал с названием `WhatsApp test`,
дождитесь статуса **Подключён** и закройте форму. В другом терминале:

```bash
python scripts/run_wazzup_partner_simulator.py --site test16.localhost --incoming --channel "WhatsApp test" --text "Первое входящее"
```

Откройте **Лиды → Partner simulator contact → Переписка**, выберите разговор
тестового канала и отправьте ответ. Дождитесь статуса **Отправлено**. Повторите
команду с другим текстом: новое входящее попадёт в тот же разговор.
Для личного Telegram укажите его название в `--channel`. Launcher и обычный
worker должны продолжать работать. API-ключи, UUID и production UI для команды
не нужны: это dev-only управление loopback simulator через настоящий callback.

### Legacy User API v3

Существующие v3 каналы продолжают работать. Их настройка скрыта по умолчанию;
для dev/admin доступа нужен site config `wazzup_legacy_ui_enabled=1`.
После включения в поле **Провайдер** формы **Новый канал** появляется **Wazzup User API v3 (устаревший режим)**.
Следующие инструкции относятся только к этому режиму.

### Выбор legacy-канала

1. Подключите WhatsApp или личный аккаунт Telegram в Wazzup и получите API-ключ этого аккаунта.
2. В CRM откройте **Новый канал → Провайдер: Wazzup User API v3 (устаревший режим)**. Выберите **WhatsApp** или **Личные чаты Telegram**. Для бота выберите отдельного провайдера **Telegram-бот**.
3. Введите **API-ключ Wazzup**. При создании следующего канала того же аккаунта можно выбрать **Источник API-ключа** — ранее сохранённый канал Wazzup. CRM скопирует секрет на сервере без показа его значения. Если одновременно введён новый ключ, используется он.
4. Нажмите **Загрузить каналы Wazzup** и выберите нужный канал. CRM заполнит мессенджер и `channelId`. Загрузка списка не сохраняет введённый ключ или другие изменения.
5. При ручном вводе укажите именно `channelId` в формате UUID v4. Номер телефона или имя пользователя (`plainId`) не подходят.
6. **Активен в CRM** разрешает обработку сообщений этим каналом. Включение переключателя само по себе не подтверждает подключение. Сохраните канал.

Пустое поле API-ключа при редактировании сохраняет прежний ключ. Каналу с существующими диалогами нельзя менять мессенджер и внешний ID: создайте отдельный канал.

### Приём событий и диагностика

Для входящих сообщений нужны публичный HTTPS-адрес CRM, работающие фоновые обработчики и настроенная в Wazzup подписка на `messagesAndStatuses` с адресом:

```text
https://<адрес-CRM>/api/method/crm_messenger.webhooks.wazzup.receive
```

В общих настройках CRM откройте **Вебхуки**, сохраните **Общий секрет вебхуков** и согласуйте этот секрет с `crmKey`, переданным Wazzup при настройке интеграции. Это другой ключ, не API-ключ Wazzup. Согласно документации, Wazzup отправляет заголовок `Authorization: Bearer <crmKey>` только когда `crmKey` настроен; без совпадающего ключа CRM отклонит событие. Изменять общую подписку аккаунта Wazzup нужно осознанно: её могут использовать другие интеграции. CRM не регистрирует и не исправляет эту подписку автоматически.

Откройте сохранённый канал и нажмите **Проверить сохранённую конфигурацию**. При несохранённых изменениях канала или общих настроек кнопка недоступна. Повторное нажатие обновляет диагностику:

- **Доступ к API** — подходит ли ключ для чтения конфигурации;
- **Выбранный канал Wazzup** — найден ли нужный мессенджер и активен ли он у провайдера;
- **Подписка на вебхуки** — совпадает ли адрес с этой CRM и включены ли сообщения и статусы;
- **Настройки вебхуков CRM** — есть ли публичный HTTPS-адрес и сохранённый секрет;
- **Фактическое входящее событие** — когда CRM успешно обработала реальное событие с проверенной авторизацией. Проверочный запрос при регистрации вебхука это состояние не подтверждает;
- счётчики событий и вложений — сколько ожидает обработки и сколько завершилось ошибкой.

Успешная проверка API и подписки не доказывает приём сообщений и не включает канал автоматически. Для проверки отправьте реальное сообщение подключённому аккаунту и дождитесь его появления в CRM; отдельно проверьте исходящий ответ и изменение статуса. Отсутствие событий показывается нейтрально. Смена ключа, внешнего ID или общих настроек требует новой проверки.

Из CRM можно отправлять текст, изображения, файлы, аудио, MP4-видео и ответы с цитатой существующего сообщения. Отправляется одно вложение без текста за запрос: текст и файл отправляйте отдельными сообщениями. Лимит исходящего файла — 10 MB, фотографии Telegram — 5 MB. Запись голосового сообщения из CRM через Wazzup не поддерживается.

## Важное ограничение

В прямых интеграциях новый диалог инициирует клиент: он должен сначала написать боту, сообществу или продавцу на Avito. После этого CRM сохранит внешний ID диалога и сможет отправлять ответы. Для первого сообщения через Wazzup нужен номер телефона клиента; в уже известном диалоге CRM использует сохранённый внешний ID.

## Если канал не подключается

1. Нажмите **Обновить статус** и проверьте сообщение об ошибке.
2. Убедитесь, что токен действителен и относится к выбранному боту или сообществу.
3. Проверьте доступность CRM по HTTPS из интернета, DNS и полную цепочку TLS-сертификата.
4. Для MAX убедитесь, что используется порт `443` и бот прошел модерацию.
5. Для VK проверьте, что включены сообщения сообщества и ключ имеет необходимые права.
6. Для Avito проверьте Client ID/Client Secret. Если список чатов доступен, отсутствие подписки ограничивает только переписку в CRM: подключите канал для автоматического создания лидов. Если API не возвращает сами чаты, проверьте права аккаунта в Avito.
7. Для диагностики будущих событий можно временно включить **Хранить подробные данные webhook-событий**. Payload может содержать текст и персональные данные клиента; секреты скрываются. После проверки выключите настройку.
8. После исправления настроек снова нажмите **Проверить** и **Подключить / исправить**.

Для разработчиков: [локальный сквозной сценарий Wazzup](../../crm_messenger/docs/wazzup_local_e2e.md)
запускается из соседнего репозитория `crm_messenger` командой
`../../env/bin/python scripts/run_wazzup_local_e2e.py --artifacts /tmp/wazzup-local-e2e-artifacts`.
Он проверяет WhatsApp и личный Telegram через настоящий CRM UI, HTTP Frappe,
отдельную БД/очередь и HTTP-имитатор, включая приватный файл и `unknown` без resend.
Текущие БД не сбрасываются. Проверка не подтверждает доставку на реальном аккаунте.
