# Телефония — этап 4, локально

Стенд: <http://127.0.0.1:8522/crm/telephony>. Реализация находится в
`/Users/g-karim/frappe/crm-exolve-20261022/apps/crm`. Production не изменялся.

## Как пользоваться

1. В карточке звонка открой **«Разбор разговора»**. Для записи доступна команда
   **«Анализировать запись»** после отдельной настройки AI.
2. AI сохраняет краткий итог и договорённости отдельно от заметки менеджера.
   **«Исходная расшифровка»** содержит результат распознавания без переписывания
   моделью итогов. Кнопка времени перемещает существующий плеер; второго плеера нет.
   Во время живого звонка переход/воспроизведение записи заблокированы.
3. Поиск внутри расшифровки фильтрует фрагменты. Общий поиск журнала находит
   исходные расшифровки, включая доступные прежние версии, а также номера и клиентов.
   Переключатель версии появляется при нескольких анализах. Если запись заменена,
   прежний разбор сохраняется, но его метки не перемещают новую запись.
4. **«Проверить и создать задачу»** открывает обычное подтверждение: название,
   лид/сделка, исполнитель, срок. Можно выбрать другую доступную карточку.
   До подтверждения задачи нет. После — это штатная CRM Task с назначением,
   уведомлениями и явной связью с исходным звонком. Потеря HTTP-ответа позволяет
   повторить тот же сохранённый запрос без второй задачи.
5. **«Аналитика»** открывает показатели всей доступной серверной истории,
   независимо от числа загруженных страниц. Период, поиск, вкладка, сотрудник,
   линия и итог совпадают с журналом. Нажатие сотрудника возвращает в его журнал.

## Что именно считается

- Всего, входящие/исходящие, завершённые, пропущенные входящие, записи,
  суммарная/средняя длительность завершённых. `Completed` — статус журнала;
  сам по себе он не доказывает состоявшийся разговор у всех провайдеров.
- Сохранённые итоги и показатели по участнику звонка: receiver для входящих,
  caller для исходящих. Это не изменение статуса провайдера и не выручка/конверсия.
- Уникальные явно связанные CRM Task: открытые, выполненные, отменённые,
  просроченные по фактическому сроку. Недоступные задачи/клиенты не учитываются.
- Скорость — медиана от начала пропущенного до начала **явно подтверждённой
  исходящей попытки**. В пропущенном с итогом «Перезвонить» выбери нужный звонок
  в блоке **«Фактическая попытка перезвона»** и подтверди связь. Кандидаты по номеру
  и времени сами ничего не связывают. Выполненная задача не доказывает звонок,
  а попытка не доказывает ответ. Показывается число подтверждённых связей.
- История ограничена реально импортированными звонками и текущими правами.
  В очереди внимания сохраняется правило этапа 3: возраст звонка не скрывает
  актуальную работу. Фильтр периода для этой очереди отключён.

## AI и расходы

AI **выключен по умолчанию** при установке. На этом локальном стенде 23 октября
он включён по прямому запросу пользователя с существующим CRM-ключом из production.
Ключ Exolve не является ключом AI. Управляющие настройки доступны System Manager /
Sales Manager через **«AI и бюджет»**. Лимит стенда — $1 в день, резерв $0.25;
лимиты общего ключа на стороне провайдера не изменялись.

- Серверный секрет: `CRM_CALL_ANALYSIS_API_KEY` либо `crm_call_analysis_api_key`
  в конфигурации этого сайта. Секрет не возвращается браузеру. Сохранение ключа
  не включает AI. Старые фоновые задания и автоматический анализ при сохранении
  звонка отключены; прежние результаты доступны для чтения.
- Стандартный режим требует отдельный OpenRouter key с `limit_reset=daily`,
  конечным USD-лимитом не выше дневного бюджета CRM и включённым учётом BYOK.
  Этот лимит провайдера является денежным ограничением. Локальный резерв
  (по умолчанию $0.25 на анализ при $1 в день) отдельно предотвращает лишние
  параллельные запросы; это резерв, а не обещание фиксированной цены за звонок.
- Для явно разрешённого общего ключа поддержан серверный флаг
  `crm_call_analysis_allow_shared_key=true`. Он включён только на локальном сайте.
  До запроса проверяются авторизация и доступные средства (`GET /key`, `GET /credits`),
  актуальный тариф STT и верхняя стоимость STT + ограниченного итога. Эта сумма
  должна помещаться в локальный резерв. Все допуски остаются сериализованными,
  неизвестная цена блокирует продолжение. Провайдерские настройки общего ключа
  не меняются; локальный бюджет учитывает только запросы этого стенда.
- Дневной резерв сериализуется общей блокировкой и актуальными locking reads:
  ранний snapshot двух запросов не позволяет обойти лимит/создать два активных
  анализа одного звонка. При смене бюджетного дня очередь пересчитывает допуск;
  уже начатый анализ останавливается перед следующим платным шагом и требует
  отдельного продолжения. Настройки имеют revision CAS.
- STT: `openai/whisper-1`, явный `language=ru`, `verbose_json`, segment timestamps.
  Перед загрузкой сверяется duration pricing через отдельный каталог transcription;
  неизвестные измерения тарифа/повышение выше установленной границы блокируют запрос.
  Итог: `google/gemini-3.1-flash-lite-preview`, ограничение вывода 1800 токенов,
  JSON и ограничение цен провайдера. Инструкции из речи считаются данными.
- Размер до 25 МБ; фактическая длина до 10 минут проверяется локальным `ffprobe`
  с ограниченными протоколами/демультиплексорами. Оригинальный звук не перекодируется
  и не перезаписывается. SHA-256 связывает анализ с прочитанными байтами.
- До каждого платного шага сохраняется его намерение и повторно проверяются
  включение, расходы, пользователь, звонок и его клиент. Платные HTTP-запросы
  не повторяются автоматически. Ответы ограничены по размеру и времени.
- Сырой ответ STT сохраняется до проверки; исходный текст, метки, ответы и итог
  после первого сохранения неизменяемы. Ошибка итога не удаляет расшифровку;
  новый явный повтор использует её и оплачивает только следующий шаг.
- `usage.cost` фиксирует фактические USD-расходы. Неизвестная стоимость/потерянный
  ответ/оборванный worker удерживают резерв и приостанавливают новые анализы.
  Менеджер сверяет полный расход с журналом провайдера, указывает номер операции
  и подтверждает сумму. Сверка не запускает работу и оставляет AI выключенным.

Документация провайдера, проверенная 23 октября 2026:
[STT](https://openrouter.ai/docs/guides/overview/multimodal/stt),
[каталог transcription](https://openrouter.ai/api/v1/models?output_modalities=transcription),
[данные и лимит ключа](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key),
[ограничения цены chat](https://openrouter.ai/docs/guides/routing/provider-selection#max-price).
Поддержка меток зависит от модели; при их отсутствии показывается исходный текст
без выдуманных времён. Legacy-текст помечается как результат прежнего анализа,
его исходность и временные метки не объявляются доказанными.

## Локальный запуск и проверка

`config/start_demo.py` запускает только собственные web/socket/redis, importer Exolve
и `config/run_call_ai.py`. AI-worker обрабатывает только явно поставленные анализы
этого сайта; общий scheduler остаётся paused, email muted. Для будущего иного
окружения потребуется отдельный процесс этой очереди; production этим кодом не
включается.

До изменений сохранены исходники, БД, конфигурация, файлы и превью записей.
Доказательства: `evidence/telephony-stage4-20261023/`; основные проверки:
`config/test_telephony_stage4.py`, `config/check_telephony_stage4.py`,
`config/check_stage4_admission.py`, `config/regress_telephony_stage3_for_stage4.py`.
Browser QA использует настоящий локальный CRUD с синтетическими ASR/аудио и
заблокированным внешним транспортом. Тестовые записи удаляются по точным ID.
Живое качество ASR/AI и обычный разговор с микрофоном остаются отдельной приёмкой;
пользователь отложил разговор. Новые звонки, SMS и production не выполнялись.

Итог приёмки: 702 frontend-теста, 142 серверных теста, два сценария конкурентного
допуска и браузерные сценарии этапов 4/3 прошли. Сохранены все поля исходных
бизнес-записей, 4771 прежний asset и превью записи. Для накопления задач при
выключенных общих workers только у этого сайта `max_queued_jobs=5000`; очередь
не очищалась и не запускалась. Остальная конфигурация сохранена побайтно по
значениям полей. Подробный итог: `evidence/telephony-stage4-20261023/result.json`.

## Подключение общего CRM-ключа — 23 октября 2026

По запросу пользователя существующий `crm_call_analysis_api_key` прочитан по SSH
из активного production bench и сохранён только в локальном site_config.json
с правами 0600. Секрет не выводился и не попал в исходники. Запросы идут через
уже работающий локальный HTTP proxy 127.0.0.1:10809; SOCKS-зависимости не требуются.
Production-файлы и лимиты ключа не менялись.

Первый допуск к 34-секундной записи остановлен правами прежнего участника до
платного запроса; отказ сохранён с нулевой стоимостью. Анализ теперь проверяет
доступ к Exolve-записи перед очередью и показывает недоступность в интерфейсе.
Другая существующая запись текущего пользователя содержала старое значение
`reference_doctype=CRM Lead` без имени клиента: чтение этого известного default
нормализовано как отсутствие связи, без переписывания Call Log. По-прежнему
проверяются реальные именованные клиентские карточки и участие в Exolve-звонке.

Успешно обработана сохранённая запись 22.2 секунды: исходный ASR, 2 сегмента,
отдельный итог, цена $0.0024055. Задач не предлагалось и не создавалось. Браузер
проверил настоящий результат и переход по метке в исходной записи. Исходные
бизнес-записи, заметки и прежнее превью сохранены. Новых звонков/SMS не было.
Проверки: 702 frontend-теста, 147 серверных тестов, build, lint и browser acceptance.
Доказательства: `evidence/ai-connection-20261023/`.
