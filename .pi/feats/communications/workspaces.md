# Телефония и общий входящий ящик EXP CRM

Концепция от 22 октября 2026, актуализирована 24 октября. **Телефония**
реализована локально: `/crm/telephony`. Общий ящик **Мессенджер** также реализован:
`/crm/messenger`; [план, сценарии и ограничения](./messenger.md).
Вызов из карточки и свёрнутый активный звонок сохранены. Production и подключения
рабочих каналов не входят в эту реализацию. Ниже сохранена исходная концепция
и исследование конкурентов; фактическое состояние описано в документах этапов.

## Реализованная локальная Телефония

В боковом меню «Телефония» заменяет Call Logs. Слева — журнал по датам с поиском
по имени/номеру, периодом, «Моими звонками» и фильтрами входящих, исходящих,
пропущенных. Записанные звонки отмечены прямо в списке; отдельная вкладка
«С записью» удалена по обратной связи 23 октября. Справа — детали, запись с перемоткой, перезвон и
доступные карточки клиента. Имена берутся из явной связи с основным контактом
сделки, с независимой проверкой прав. По совпадению телефона карточки не склеиваются.
Из подробностей доступны прежние заметки, задачи и действия.

Номеронабиратель ищет доступные лиды/сделки/контакты либо принимает номер.
Выбор клиента и открытие звонилки не создают звонка. Соединение настроенного
сотрудника восстанавливается автоматически; микрофон включается только при
вызове/ответе. SIP-данные не попадают в состояние
страницы. Воспроизведение записей приостанавливается во время живого звонка.
На телефоне список, детали и набор открываются последовательно с возвратом.

Старый табличный журнал, сохранённые представления и ссылки
`/crm/call-logs?open=...` сохранены; журнал доступен кнопкой «Список».
Новые API только читают CRM Call Log; обновление списка не запускает импорт,
звонок или платный AI. При загрузке CRM отдельный компонент звонилки автоматически
подключает SIP настроенного сотрудника. Полнота истории ограничена
прежним механизмом Exolve, описанным в контракте пилота.

Итоги, задачи на перезвон, очередь **«Требуют внимания»**, фильтры линии,
сотрудника и результата реализованы локально в [третьем этапе](../telephony/stage3.md).
Аналитика остаётся четвёртым этапом. Серверное восстановление истории и личные
черновики описаны во [втором этапе](../telephony/stage2.md).
`crm_messenger` установлен на тот же тестовый сайт, но каналы ещё не подключены.
Заметки и задачи во время разговора реализованы локально в отдельной панели:
[сценарий и место сохранения](../telephony/call-work-notes.md). Они сразу пишутся
в выбранный лид/сделку; связь с последующей статистикой звонка пока не автоматизируется.

## Предложение

Заменить пункт Call Logs на **Телефония**, а рядом добавить **Входящие** с
пояснением «Мессенджеры и почта». Это два рабочих места с общим контекстом клиента.
Названия операторов остаются в настройках подключения. SMS после интеграции
показывать во Входящих; из звонка открывать нужную переписку клиента.

Список обращений должен сразу отвечать на вопрос «Кому нужно ответить или
перезвонить?». Подробности, запись и карточки клиента открываются рядом.

## Экран Телефония

```text
Телефония                                 Подключить гарнитуру    Позвонить
Все   Пропущенные   Нужен перезвон   С записью
Поиск по клиенту / номеру                  Период  Сотрудник  Линия
┌─────────────────────────────────────────┬───────────────────────────────┐
│ Сегодня                                 │ Алексей Соколов              │
│ ↙ Пропущен · Алексей · 14:20             │ Контакт · Компания           │
│ ↗ Состоялся · Мария · 13:48 · 03:12      │ Лид / связанные сделки       │
│ ↗ Без ответа · Новый номер · 12:10       │                               │
│                                         │ Запись: ▶ 00:00 / 03:12      │
│ Результат, сотрудник, длительность       │ Заметка / результат          │
│ и наличие записи видны без открытия      │ Перезвонить · Создать задачу │
└─────────────────────────────────────────┴───────────────────────────────┘
```

- «Позвонить» открывает панель набора с поиском контакта или вводом номера.
  Подключение микрофона — явное действие пользователя. Звонок начинается
  отдельным нажатием; открытие страницы и выбор клиента не набирают номер.
- Статус гарнитуры и выбранная исходящая линия видны в этом разделе.
  Название провайдера не занимает место в общей шапке CRM.
- Запись слушается в боковой панели с перемоткой. Во время живого разговора
  воспроизведение записи не должно мешать звонку. «Готовится», «Недоступна» и
  «Нет записи» — разные состояния. Расшифровка и AI — последующие возможности.
- Активный звонок сохраняется при навигации по CRM; после сворачивания доступны
  длительность и возврат к микрофону, DTMF и завершению. На мобильном экране
  панель набора и детали открываются последовательно во весь экран.
- «Пропущен» — результат попытки; «Нужен перезвон» — отдельная рабочая задача
  с ответственным и завершением. Просмотр записи не закрывает такую задачу.
- Сначала журнал, фильтры, набор и записи. Аналитика команды и настройки линий
  — вторичные экраны, когда есть данные и соответствующие права.

## Экран Входящие

```text
Входящие                  Поиск по клиентам и переписке
Мои  Без ответственного  Все доступные  Ждут ответа  Отложены  Закрыты
Каналы / аккаунты
┌──────────────────────┬───────────────────────────────────┬────────────────┐
│ Диалоги              │ Мария · Telegram · Отдел продаж   │ Клиент         │
│                      │ Ответственный · Открыт            │ Компания       │
│ Telegram · Мария  ●2 │                                   │ Контакты       │
│ Email · Алексей      │ История переписки                 │ Лиды           │
│ VK · Новый клиент    │ Текст, документы, голосовые       │ Сделки         │
│                      │                                   │ Задачи         │
│ Канал, превью, время │ Ответ / Внутренняя заметка         │ История звонков│
│ и ответственный      │ Явный аккаунт отправителя         │                │
└──────────────────────┴───────────────────────────────────┴────────────────┘
```

- Глобальный список показывает переписку из доступных лидов и сделок.
  В карточке и общем ящике открывается один исходный диалог. Сообщения не
  копируются в каждую сделку; связи и выбранный контекст отображаются рядом.
- У клиента может быть несколько сделок и каналов. Их можно показать вместе
  в профиле, сохраняя отдельные транспортные цепочки. Email цепочками, Telegram
  и VK не склеиваются автоматически в одну переписку по совпадению имени.
- Для почты нужен отдельный вид редактора: тема, To/CC/BCC, цитирование,
  подпись, вложения. Для мессенджера — компактный редактор с возможностями
  конкретного канала. SMS Exolve позже станет ещё одним каналом.
- Статусы «Ждёт нашего ответа», «Ждём клиента», «Отложен», «Закрыт» помогают
  управлять работой. «Прочитано» и «Закрыт» не заменяют друг друга.
- Назначение, передача, черновики, внутренние заметки и шаблоны — полезные
  следующие функции. Индикатор «сотрудник уже отвечает» потребует отдельного
  серверного механизма; его нельзя рисовать как действующую возможность.
- Непривязанные обращения требуют отдельного доступа очереди. Пока такой
  модели нет, для обычных пользователей сохраняется существующий запрет.
- На узком экране: сначала список → диалог → контекст клиента. Черновик и
  позиция прокрутки сохраняются при возврате, с разделением по пользователю.

## Правила реализации

Сохранять CRM Call Log, Messenger Message/Conversation и Communication как
исходные записи. Общий ящик — представление над ними; допустим индекс поиска
и списка, восстанавливаемый из исходных данных. Отдельные рабочие состояния,
назначения и связи допустимы, копии истории сообщений не нужны.

Фильтровать права на сервере до подсчётов, поиска, превью и пагинации.
«Все» означает все доступные пользователю обращения. Личная почта не становится
общей из-за появления Входящих. Проверять право чтения, отправку от выбранного
аккаунта и скачивание вложений отдельно.

Текущий get_conversations требует CRM-контекст; обходить его прямым общим
get_all нельзя. Глобальный API должен сам проверять права каждого обращения.
Чтение списка не должно автоматически отправлять клиенту read receipt.
Существующий общий unread_count нельзя выдавать за личный счётчик сотрудника.

Сохранять старые URL /call-logs и открытие конкретной записи; новый раздел
должен переиспользовать существующие API проигрывания и проверки прав.
Прочтение сообщения, событие CRM Notification и закрытие рабочего обращения
имеют разный смысл. Общий ящик клиентской переписки не заменяет уведомления
EXP Omniverse и внутренние командные чаты EXP One.

Для отправки повторно использовать client_request_id и статусы доставки
источника. Истечение HTTP-запроса не означает ни «отправлено», ни «не отправлено».
Фоновая синхронизация нужна независимо от открытой вкладки браузера.

## Порядок следующей работы

1. Локальная Телефония: новый экран над существующим журналом, номеронабиратель,
   запись и контекст клиента; сохранить старые ссылки. Уточнить хранение задач
   перезвона и не подменять их результатом звонка.
2. Локальные Входящие на синтетических данных: список, диалог, контекст,
   маршрутизация из лида и сделки, состояния и проверки доступа. Без отправки.
3. Для установленного на отдельном стенде crm_messenger расширить
   права и связи со сделками, согласовать семантику прочтения. Добавить адаптер
   Communication и цепочки email без дублирования истории.
4. Проверить по одному реальному каналу и общему почтовому ящику после выбора
   аккаунтов и разрешения на отправку; отдельно принять входящие Exolve и SMS.
5. Затем очереди команды, отложенные обращения, шаблоны и аналитика. Выпуск
   в production — отдельный этап.

Приёмка первого экрана: номер не набирается при открытии, диалог открывается
из карточки, разговор переживает переход между разделами, запись и перемотка
работают, закрытые записи недоступны без прав, мобильный экран не переполняется.
Для Входящих дополнительно: один диалог из разных карточек без дублей,
неоднозначная связь с несколькими сделками, раздельные личные/общие ящики,
новое сообщение во время чтения, переключение аккаунта с черновиком,
повтор отправки после неизвестного результата и проверка прав после отзыва.

## Визуальное направление

Сохранить шрифт и компоненты Frappe UI. Для иллюстративного макета: фон #171717,
панель #202020, выбор #2a2a2a, основной текст #f5f5f5, вторичный #a3a3a3,
акцент EXP #06b6d4. Светлая тема использует ту же иерархию. Статус обозначать
текстом и значком, цвет использовать дополнительно.

Плотная рабочая компоновка с выравниванием слева, без крупных декоративных
метрик. Главный визуальный акцент — выбранное обращение и его содержимое.
Фильтры помогают разбирать очередь, контекстная панель сокращает переходы.
Такой макет продолжает текущий интерфейс CRM и подходит ежедневной работе.
